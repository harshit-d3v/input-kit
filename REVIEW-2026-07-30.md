# Review of the 29 untested packages — 2026-07-30

Working notes for the second review pass. The first pass covered `hooks`, `toast`,
`combobox`, `table`, `form`, `dropzone` (all published) — see `KNOWN-ISSUES.md`.

This pass reviews the packages that carry no test suite. Each entry lists defects that
are real — reachable from the documented API, not hypothetical.

Status legend: **[bug]** wrong behaviour · **[type]** unusable/wrong types ·
**[a11y]** accessibility · **[perf]** avoidable work · **[api]** misleading surface

## Status: fixed, not yet published

Every defect below is **fixed in the working tree** as of 2026-07-30. Verified after
the changes: `npm run typecheck` clean across all 41 packages and the docs site,
`npm run build` clean across all 41, `npm run test` **718 passing / 0 failing** —
the same total as before, so nothing regressed — and `node scripts/check-demos.mjs`
parses 41/41 demos.

No versions have been bumped and nothing has been published. Publishing needs an npm
OTP from the maintainer.

All 29 untested packages have now been reviewed. `clipboard` was the only one with no
defects found.

## Worst first — all fixed

| | Package | Defect |
|---|---|---|
| 1 | `gauge` | Horizontal `LinearGauge` renders ~1% full at every value — a 0–1 fraction interpolated into a CSS percent |
| 2 | `split` | Controlled `sizes` is an unbreakable infinite render loop |
| 3 | `otp` | `onComplete` re-fires every render once the code is full — consumers submit repeatedly |
| 4 | `dropzone` | `dragenter` throws in Chrome whenever `accept` uses file extensions |
| 5 | `menu` | `DropdownMenu` cannot be dismissed by clicking away |
| 6 | `markdown` | `//evil.com` defeats the URL sanitiser |
| 7 | `tree` | Every consumer callback fires from inside a `setState` updater — doubled under StrictMode |
| 8 | `mask` | `MaskedInput` loops forever when `showMaskOnFocus={false}` |
| 9 | `upload` | Image previews leak their object URLs; callbacks get a permanently stale file |
| 10 | `resize` | `useResizeObserver<T>()` returns a ref that `<T>` rejects — the generic is decorative |

Three of these (`gauge`, `split`, `otp`) made the package's headline feature wrong in
its default configuration.

## Behaviour changes worth a version bump

These fixes change observable output, so they are not pure patches:

- **`currency`** — fraction digits now follow the currency (`formatCurrency(1234, { currency: 'JPY' })` is `¥1,234`, was `¥1,234.00`). `parseCurrency` takes an optional `locale`; `convertCurrency` takes an optional rate table.
- **`mask`** — the `A` mask character now uppercases, as it has always been documented to.
- **`i18n`** — `pluralize` follows CLDR categories per locale instead of `count === 1`; `mergeMessages` is a deep merge.
- **`tree`** — collapsed children are unmounted rather than clipped; `useTree` accepts controlled `expandedIds` / `selectedIds`.
- **`gauge`** — the exported `describeArc` now emits its path start-to-end (same shape, opposite direction) so a dash animation fills the right way.
- **`paste`** — `preventDefault` no longer applies when the paste lands in an input, textarea, or contenteditable.
- **`tabs`** — `Tab` / `TabPanel` are typed as `TabProps` / `TabPanelProps`; the `__`-prefixed internals are no longer in the public surface.
- **`split`** — `Pane` no longer sizes itself (the wrapper always did); `CollapsibleSplit` tracks a changing `collapsed` prop.

---

## clipboard — clean

No defects found. Secure-context branch, `execCommand` fallback, timer cancelled on
unmount, `copy` rejects nothing and reports success as a boolean. The only nit is that
`copy()` can resolve after unmount and call `setCopied` on a dead component; React 18
no longer warns and the timer is already cleaned up, so this is not worth changing.

## fullscreen

1. **[bug] `isFullscreen` ignores which element is fullscreen.** The listener sets it
   from `getFullscreenElement(document) !== null`, so `useFullscreen(myRef)` reports
   `true` when some *other* element entered fullscreen. For a ref-scoped hook the state
   has to be `getFullscreenElement(document) === elementRef.current`.
2. **[bug] `toggle()` has the same confusion** — it exits whenever anything is
   fullscreen, so with two panels on a page, toggling panel B while panel A is
   fullscreen exits A instead of entering B.
3. **[api] `enter`/`exit` swallow every error into `catch {}` and return `void`.**
   A browser that blocks the request (no user gesture) or lacks the API is
   indistinguishable from success. Returning `Promise<boolean>`, or at least surfacing
   an `isSupported` flag, would make the failure visible.

## online

1. **[bug] Hydration mismatch.** `useState` seeds from `navigator.onLine` during
   render, so a client that is offline at hydration renders different markup than the
   server, which always seeds `true`. `useSyncExternalStore` with a separate server
   snapshot is the fix; it also removes the duplicated listener bookkeeping.
2. **[perf] Both `useState` calls use a non-lazy initializer**, so the whole state
   object — including two `new Date()` allocations — is rebuilt on every render and
   thrown away. Wrap in `() => ...`.
3. **[bug] `new Date()` during render** makes the first render impure; under
   StrictMode's double render the two runs disagree.

## search

1. **[bug] `onSearch` fires on mount.** The debounce effect has no first-run guard, so
   `useSearch({ onSearch })` and `<SearchInput onSearch>` both dispatch a search for
   the initial value ~300 ms after mount, before the user has typed. Every consumer
   pays for one spurious query per mount.
2. **[bug] `clear()` triggers a second dispatch.** It sets `value` and `debouncedValue`
   to `''` directly, then the effect re-runs on the `value` change and calls
   `onSearch('')` again after the debounce.
3. **[api] `SearchInput` never exposes the debounced value or a clear affordance**,
   so the component version cannot do what the hook version does.

## currency

1. **[bug] Fraction-digit defaults corrupt zero-decimal currencies.** `defaultOptions`
   pins `minimum/maximumFractionDigits` to `2`, overriding the per-currency defaults
   `Intl` would apply. `formatCurrency(1234, { currency: 'JPY' })` yields `¥1,234.00`;
   yen has no minor unit. Same for KRW, VND, CLP. The defaults must be `undefined`.
2. **[bug] `parseCurrency` is locale-blind** while the rest of the module is
   locale-aware. It strips everything but `[\d.-]`, so the German
   `formatCurrency(1234.56, { locale: 'de-DE', currency: 'EUR' })` output
   `"1.234,56 €"` parses back to `1.234`. Round-tripping its own output loses three
   orders of magnitude. It also takes no `locale` argument to fix this with.
3. **[bug] `getCurrencySymbol` throws on an unknown code.** `new Intl.NumberFormat`
   raises `RangeError` for an invalid currency, and it is outside the `try` the
   `|| currency` fallback implies was intended. `getCurrencySymbol('XYZ')` throws
   rather than returning `'XYZ'`.
4. **[api] `convertCurrency` ships hardcoded rates that were current around 2021.**
   A function named "convert" that silently returns figures years out of date is worse
   than no function; it should take a rate table, or be dropped.
5. **[perf] `useCurrency` builds a fresh `Intl.NumberFormat` on every render**
   (`getCurrencySymbol` is called in the render body) and returns new `format` /
   `formatNumber` identities each time, so every memoised consumer re-renders.

## resize

1. **[type] `useResizeObserver<T>`'s ref cannot be attached to a `T`.** The return type
   is hardcoded `RefObject<HTMLElement>` and the generic is erased by the
   `ref as RefObject<HTMLElement>` cast, so `useResizeObserver<HTMLDivElement>()`
   hands back a ref that `<div ref={ref}>` rejects — `HTMLElement` is not assignable to
   `HTMLDivElement`. The generic parameter is decorative. (Same shape as the `table`
   and `combobox` generics fixed in the first pass.)
2. **[perf/bug] The observer tears down and re-attaches whenever `onResize` changes
   identity.** `onResize` is in the dependency array, and it is normally an inline
   arrow, so every render disconnects and re-observes. It should be held in a ref, as
   the `hooks` package now does after the same finding.
3. **[bug] Elements that mount later are never observed.** The effect reads
   `ref.current` once and does not re-run when it changes, so a conditionally rendered
   target stays unmeasured forever. A callback ref fixes it.
4. **[bug] `getBreakpoint(width, {})` throws.** With an empty map `sorted` is empty and
   the fallback indexes `sorted[-1][0]` on `undefined`.
5. **[bug] `useElementBounds` misses window resizes.** It listens for `scroll` and
   element resizes, but a viewport resize that moves the element without changing its
   size leaves stale bounds.

## json

1. **[bug] Circular data crashes the component.** `renderValue` recurses with no seen
   set and no depth cap, so any cyclic object overflows the stack and takes the app
   down. `formatJSON` has the same problem for the copy button, though there it is
   caught.
2. **[a11y] The expand/collapse control is a bare `<span onClick>`.** No `role`, no
   `tabIndex`, no key handler, no `aria-expanded` — unreachable by keyboard and
   invisible to assistive tech. It should be a `<button>`.
3. **[bug] Non-plain objects render as empty.** `Date`, `Map`, `Set` and `RegExp` all
   satisfy `typeof === 'object'` and are handed to `JSONObject`, which lists
   `Object.keys()` — zero for all of them — so a date shows as `{0 keys}`.
4. **[bug] `undefined` members render as nothing.** No branch matches
   `typeof undefined`, so `renderValue` returns `null` and the row is blank rather
   than showing the key.

## i18n

1. **[bug] `pluralize` computes the plural rule and then ignores it.**
   `pluralRules.select(count)` is called, and the two- and three-part branches — the
   ones the docs show — instead hardcode `count === 1`. That is English's rule.
   Russian `"товар | товара | товаров"` with `count: 21` must select the *first* form;
   this returns the third. The whole point of pulling in `Intl.PluralRules` is lost.
2. **[bug] Any translation containing `|` is mangled.** `pluralize` splits
   unconditionally whenever `count` is passed, so `t('crumbs', { count: 2 })` over
   `"Home | Docs | API"` returns `"Docs"`.
3. **[bug] `mergeMessages` is a shallow merge.** Translation files are nested by
   design, so merging `{en:{common:{a}}}` with `{en:{common:{b}}}` drops `a` — the
   exact case the helper exists for.
4. **[bug] `LocaleSwitcher` labels options in the wrong language.**
   `new Intl.DisplayNames(availableLocales, …)` passes the list of locales *being
   listed* as the locale to *display them in*. It should be the active `locale`, so
   the menu reads in the language the user currently has selected.
5. **[perf] An inline `config` prop re-renders every consumer.**
   `<I18nProvider config={{ locale, messages }}>` — the documented usage — produces a
   new `messages` identity per render, invalidating `availableLocales`, `t` and the
   whole context value each time.

## mask

1. **[bug] `MaskedInput` can loop forever when `showMaskOnFocus={false}`.** The sync
   effect conforms `controlledValue` with the `guide` *prop*, but the hook it feeds was
   constructed with `guide: showMaskOnFocus ? guide : false`. With `guide` true and
   `showMaskOnFocus` false the two conformed strings can never be equal, so the effect
   calls `setValue` on every render and re-renders on every call.
2. **[bug] The effect re-runs on every render regardless.** `parseMask(maskInput)` runs
   in the render body and returns a fresh array, which is a dependency of `setValue`,
   which is a dependency of the effect. Every `useCallback` in the hook is likewise
   rebuilt each render, so none of the memoisation does anything.
3. **[bug] Backspace injects a literal `_` when `guide` is off.** `handleKeyDown`
   splices `placeholderChar` into the value unconditionally, but with `guide: false`
   the value holds no placeholders, so deleting a character types an underscore into
   the field.
4. **[bug] `'A'` never uppercases.** `MASK_CHARS` documents `'A'` as "any letter (will
   be uppercased)" and the shipped `masks.time12` (`'99:99 AA'`) relies on it, but no
   code path changes case, so `"10:30 am"` is accepted as-is.
5. **[bug] Caret placement counts fixed characters as input.** The caret loop counts
   every `\S` in the raw input — including the mask's own `(`, `)`, `-` separators — so
   editing anywhere but the end of a separated mask puts the cursor in the wrong place.

## otp

1. **[bug] `onComplete` re-fires on every render once the code is full.** The notify
   effect lists `[value, isComplete, onChange, onComplete]`; inline callbacks — the
   normal way to pass them — change identity every render, so a filled OTP calls
   `onComplete` again and again. Since `onComplete` is what consumers use to submit,
   this submits repeatedly. Both callbacks must go through a ref.
2. **[bug] Both callbacks also fire on mount**, before any input, with the empty value.
3. **[bug] Controlled `value` can loop.** The sync effect compares `controlledValue`
   against `value.join('')` and calls `setValue`, but `setValue` filters out characters
   that fail the type pattern — so a `value` containing a separator (`"12-34"`) never
   converges and the effect fires forever.
4. **[bug] `setValue` truncates before filtering; `handlePaste` filters before
   truncating.** The two disagree, and `setValue` is the wrong one:
   `setValue('12-345')` at `length: 4` slices to `'12-3'`, filters to `'123'`, and
   silently drops the `5`.
5. **[bug] Changing `length` after mount breaks the inputs.** The value array is sized
   by the `useState` initialiser only, so a larger `length` renders inputs whose
   `value[index]` is `undefined` — React flips them from controlled to uncontrolled.
6. **[bug] `setFocusedIndex` is called inside a `setValueState` updater** (Backspace).
   Updaters must be pure; StrictMode invokes them twice, moving focus two cells.

## tabs

1. **[api] Internal props are part of the public type.** `Tab` and `TabPanel` are
   exported typed as `InternalTabProps` / `InternalTabPanelProps`, so `__index`,
   `__selected`, `__tabRef`, `__onSelect` and friends autocomplete for consumers and
   can be passed from outside. The public `TabProps` / `TabPanelProps` are exported but
   never used as the component signatures.
2. **[a11y] Disabled tabs are removed from the tab sequence.** They render as native
   `<button disabled>`, which cannot be focused, so a keyboard user cannot land on one
   to learn it exists. APG asks for `aria-disabled` on a still-focusable element.
3. **[api] Only direct children are wired.** `TabList` clones its immediate children,
   so wrapping a `Tab` in a `<div>`, a fragment, or any component of your own silently
   produces a tab with no id, no selection state and no key handling.
4. **[perf] `firstEnabledIndex` / `lastEnabledIndex` memos never hit.** They depend on
   `tabs`, which `toTabElements(children)` rebuilds every render.

## code

1. **[bug] Blank lines render doubled.** A line with no tokens renders the string
   `'\n'` inside a `<pre>`, and the line is already its own block `<div>` — so every
   empty line in the source shows as two.
2. **[bug] Token precedence rests on sort stability.** Overlaps are resolved by sorting
   on start index alone and keeping the first, so two patterns matching at the same
   offset (`if (` matches both `keyword` and `function`) are separated only by their
   push order surviving a stable sort. It works today; nothing states the invariant.
3. **[dead] `charIndex` in `tokensByLine` is incremented and never read.**
4. **[api] `InlineCode` does not highlight.** In a syntax-highlighting package, the
   inline variant only applies theme background and text colour.

## gauge

1. **[bug] `LinearGauge` is always ~1% full — the headline defect of this pass.**
   `normalizeGaugeValue` returns `percentage` as a **fraction** (`0`–`1`), and the
   vertical branch correctly scales it (`percentageValue`, line 314), but the
   horizontal branch — the default, `vertical` is `false` — interpolates the raw
   fraction into a CSS percent: `width: \`${percentage}%\`` (line 376). A gauge at
   full value renders one percent wide. Every horizontal `LinearGauge` ever rendered
   has been wrong.
2. **[bug] `animated` does nothing on the circular `Gauge`.** The value arc is
   redrawn by changing the path's `d` attribute, which is not animatable, and the
   declared transition names `stroke-dashoffset` — a property this component never
   sets. The needle relies on transitioning `<line>`'s `x2`/`y2`, which browsers do
   not expose as CSS geometry properties. Neither element moves smoothly.
3. **[a11y] No accessible value.** For a component whose entire purpose is reporting a
   measurement, there is no `role="meter"`, no `aria-valuenow` / `valuemin` /
   `valuemax`, no accessible name — just anonymous SVG. Screen readers get nothing.
4. **[api] `colors` thresholds are compared against a percentage, not the value.**
   `getColorForValue(percentage * 100, colors)` — so with `min={0} max={200}` a
   threshold written as `{ value: 150 }` never triggers, because the comparison sees
   `0`–`100`. The field is named `value`, and the defaults (`0`/`50`/`75`) read as
   either. It needs to be one or the other, documented.
5. **[bug] Text offsets do not scale with `size`.** Font sizes are computed from `size`
   but the value and label are pinned at `center + 40` / `center + 60`, so small
   gauges overlap their own needle and large ones bunch the text near the middle.

## markdown

1. **[security] Protocol-relative URLs bypass the sanitiser.** `sanitizeUrl` returns
   any URL starting with `/` untouched as "internal", but `//evil.com` is a
   protocol-relative URL: `[click](//evil.com)` renders a link that navigates
   off-origin. The check needs to reject a second leading slash.
2. **[bug] Empty table cells shift every column after them.** Both header and body rows
   are split on `|` and then `.filter(Boolean)`, which is doing double duty — stripping
   the leading/trailing empties from `| a | b |` *and* deleting genuinely empty cells.
   `| a | | c |` becomes a two-column row, so `c` lands under the second heading.
3. **[bug] Asterisks in prose become italics.** The italic rule is
   `/^(\*|_)(.+?)\1/` with no check that the delimiter is flanked by non-space, so
   `2 * 3 * 4` renders "3" in italics. CommonMark requires a non-space character after
   the opening delimiter.
4. **[bug] No escape support.** `\*not bold\*` renders the backslashes literally;
   there is no way to write a literal `*`, `_`, `` ` `` or `[`.
5. **[bug] Nested lists render as paragraph text.** The list rules anchor the marker at
   column 0, and the paragraph rule's exclusion list uses the same anchored patterns,
   so an indented `  - sub-item` is swallowed into the preceding paragraph.
6. **[perf] An inline `components` prop remounts the whole tree every render.**
   `{ ...defaultComponents, ...customComponents }` is rebuilt in the render body; with
   the documented usage — `components={{ h1: ({children}) => <h1/> }}` — each override
   is a fresh function, so React sees a new element *type* and unmounts and remounts
   that part of the document on every parent render, discarding any state inside it.

## slider

1. **[bug] `showTicks` with `tickCount={1}` emits `NaN`.** `(i / (tickCount - 1))` is
   `0 / 0`, so every tick gets `left: NaN%`. `gauge` guards this exact division;
   `slider` does not.
2. **[bug] Touch dragging scrolls the page.** `handleTouchStart` never calls
   `preventDefault`, and neither the track nor the thumb sets `touch-action: none`, so
   on a phone the gesture is claimed by the scroller. (`split`'s gutter does set it —
   the packages disagree.)
3. **[perf] Every pointer move re-subscribes four document listeners.** The drag effect
   lists `value` and `onChangeEnd` as dependencies, both of which change on each move,
   so the whole add/remove cycle runs per frame of the drag.
4. **[bug] Likely zero-width track by default.** The wrapper is `display: inline-flex`
   with no width and the track asks for `width: 100%`; against a shrink-to-fit parent
   whose only in-flow child is that track, the percentage resolves against an
   indefinite size. A bare `<Slider />` needs an explicit width from the consumer.
   *Confirm in a browser before acting on this one.*
5. **[bug] Clicking a `RangeSlider` thumb re-runs the track's click handler.** The
   thumbs are children of the track, so `handleTrackClick` fires on the bubbled click
   and re-derives the nearest thumb from the pointer position — a press that should be
   inert can snap the value by up to half a step.

## split

1. **[bug] Controlled `sizes` is an infinite render loop.** The sync effect is
   `if (controlledSizes) setSizes(controlledSizes)` keyed on `[controlledSizes]`, and
   the documented usage passes an inline array. New identity each render → effect runs
   → `setSizesState` with a new array → re-render → new identity again. Nothing breaks
   the cycle.
2. **[bug] The exported `Pane` component does not work.** `SplitPane` already wraps
   every child in its own `<div data-pane="true">`, so a `Pane` used as a child is
   double-wrapped; its index probe walks `parentElement.children` and finds only
   itself, so it always resolves to index `0` and claims `sizes[0]`, and its
   `flex: 1 1 n%` then fights the wrapper's `flex: 0 0 calc(...)`.
3. **[bug] `CollapsibleSplit` cannot resize or be controlled.** Its `savedSize` state
   has a setter named `_setSavedSize` that is never called, so the pane is fixed-width;
   the `collapsed` prop seeds `useState` and has no sync effect, so changing it from
   the parent does nothing; and the declared `minSize` prop is unused.
4. **[bug] Changing the number of children corrupts the layout.** `sizes` is seeded
   once by `useState`, so adding a pane leaves `sizes[index]` undefined and emits
   `flex: 0 0 calc(undefined% - 4px)`.
5. **[bug] Gutter hover overwrites a caller's `style`.** `onMouseEnter` /
   `onMouseLeave` assign `e.currentTarget.style.background` imperatively, so a custom
   background passed via `style` is replaced by `#e5e7eb` the first time the pointer
   leaves and never comes back.

## sparkline

1. **[bug] `SparkBar` draws the wrong heights whenever the data contains negatives.**
   Bar height is `normalized * chartHeight`, where `normalized` is the value's position
   across the *whole* range — but once a zero line exists the height has to be the
   distance from zero. For `[-10, 0, 10]` the normalised values are `[0, 0.5, 1]`, so
   the zero bar renders half-height and the most-negative bar renders nothing.
2. **[bug] `SparkArea` breaks SSR hydration.** The gradient id comes from
   `Math.random()`, so the server and client emit different `id` / `url(#id)` pairs and
   React reports a mismatch. `useId` exists for exactly this.
3. **[bug] The draw-on animation starts part-drawn on curved lines.** `pathLength` sums
   straight-line distances between points, but `curved` defaults to `true`, and a
   bezier through those points is longer — so `strokeDashoffset` is short of the real
   length and the first stretch of the line is visible before the animation runs.
4. **[bug] Min/max markers mark every tie.** `isMin` is `value === min`, so a series
   with a repeated low renders a marker at each occurrence; a flat series marks every
   point (and `isMin` wins the ternary, so they all take `minColor`).
5. **[perf] `SparklineWithReference` memoises on `rest`,** a fresh object each render,
   so neither `useMemo` ever hits.

## paste

1. **[api] `usePaste()` hijacks paste for the entire page.** It binds to `document` and
   `preventDefault` defaults to **true**, so merely mounting the hook stops paste from
   working in every input, textarea and contenteditable on the page. The safe default
   for a document-level listener is not to cancel the event.
2. **[bug] `PasteZone` blocks paste into its own children** for the same reason — a
   text field rendered inside the zone cannot be pasted into.
3. **[bug] `pasteFromClipboard` reports text as files.** `readClipboard` loops over
   *every* MIME type of every clipboard item and wraps each in a `File`, so copying
   plain text yields `files: [text/plain, text/html]` and fires `onPasteFiles`.
4. **[bug] Synthesised files have no extension.** They are named
   `pasted-<timestamp>`, so an `acceptedTypes` entry written as `'.png'` — the
   extension form the filter explicitly supports — never matches a pasted image.
5. **[bug] Rejected files vanish silently.** `finalizePasteData` filters by type and
   size and discards what it drops, so a consumer cannot tell a paste that was
   filtered from one that was empty. This is the same defect fixed in `dropzone`
   (0.2.0) and should be fixed the same way.
6. **[bug] `usePasteZone` misses elements that mount later** — the effect reads
   `elementRef.current` once and does not re-run when it becomes non-null.

## upload

1. **[bug] Every image preview leaks its object URL.** `createPreviewUrl` calls
   `URL.createObjectURL` for each image added, and `revokePreviewUrl` runs only from
   `removeFile` and `clearFiles`. There is no unmount cleanup, so a component that
   unmounts with files still listed leaks one blob per image for the life of the
   document.
2. **[bug] Every callback receives a stale file object.** `onUploadStart`,
   `onProgress`, `onSuccess` and `onError` are all passed the `fileItem` snapshot
   captured *before* the request began, so `file.status` is always `'idle'` and
   `file.progress` is always `0`. `onProgress(file, progress)` disagrees with itself:
   the number is live, the object is not.
3. **[bug] `maxFiles` lets files through once the limit is already exceeded.**
   `addFiles` computes `allowed = maxFiles - current` and calls
   `fileArray.splice(allowed)`. When `current` is already at or over the limit,
   `allowed` is negative and a negative `splice` trims from the *end* — so adding four
   files to a full list drops two and adds the other two.
4. **[bug] `retryUpload` bypasses validation.** It resets status to `'idle'` and
   queues the id without re-running `validateFile`, so a file that was rejected for
   exceeding `maxFileSize` uploads on retry.
5. **[bug] `UploadButton` re-enables itself on the first completion.** `isUploading`
   is cleared in `onSuccess`/`onError` per file, so with `multiple` set the button
   becomes clickable again while the rest of the batch is still uploading.
6. **[bug] `formatFileSize` breaks outside its table.** Sizes ≥ 1 PB index past
   `['B','KB','MB','GB','TB']` and render `"… undefined"`; a negative input yields
   `NaN`.

## tree

1. **[bug] Every consumer callback fires from inside a `setState` updater.**
   `toggleExpand`, `expand`, `collapse`, `toggleSelect`, `select`, `deselect`,
   `toggleCheck`, `check` and `uncheck` all invoke `onExpansionChange` /
   `onSelectionChange` / `onCheckedChange` *within* the function passed to the setter.
   Updaters must be pure — StrictMode double-invokes them, so in development every one
   of these callbacks fires twice per interaction, and React is free to re-run them
   when rebasing concurrent updates. This is the single most pervasive defect in the
   package.
2. **[bug] `onExpansionChange` reports the wrong set in controlled mode.** `Tree`
   derives the rendered `expandedIds` from the controlled prop, but `toggleExpand`
   computes its callback argument from the *internal* set, which the parent never
   updates. Passing `expandedIds={['a']}` and clicking `b` reports `['b']`, not
   `['a','b']`.
3. **[a11y] Collapsed subtrees stay in the accessibility tree.** Children are hidden
   with `max-height: 0; overflow: hidden` rather than unmounted or `hidden`, so a node
   marked `aria-expanded="false"` still exposes all of its descendants to a screen
   reader. It also means the whole dataset is always in the DOM.
4. **[bug] `check(id)` and `toggleCheck(id)` disagree.** `toggleCheck` reconciles
   ancestors after cascading; `check`/`uncheck` cascade to descendants only, so calling
   `check` on every child leaves the parent unchecked while the equivalent clicks mark
   it checked.
5. **[perf] The focus effect runs on every render.** Its dependency array contains
   `tree`, the object literal `useTree` returns fresh each time. In controlled mode
   `new Set(controlledExpandedIds)` likewise invalidates `visibleIds` every render, so
   the whole tree is re-walked continuously.

## menu

1. **[bug] `DropdownMenu` cannot be dismissed by clicking away.** Outside-click and
   Escape handling live only in `useContextMenu`, which `DropdownMenu` does not use,
   and `Menu` itself binds nothing. Open one and it stays open until an item is chosen
   or the trigger is clicked again — clicking anywhere else on the page does nothing.
2. **[bug] An open submenu drives two key handlers at once.** Every mounted `Menu`
   attaches its own `keydown` listener to `document`, so with a submenu showing,
   ArrowDown advances the highlight in the parent menu *and* the submenu.
3. **[a11y] Nothing ever receives focus** — *fixed in a follow-up (0.2.0)*.
   `focusedIndex` was a background colour and nothing more: no element was focused and
   the `role="menu"` container was not focusable, so keyboard support worked only
   because the listener was global, and assistive tech was told nothing about the
   active item. Items are now real `<button role="menuitem">` elements with a roving
   tabindex; focus enters on open; the key handler is bound to the menu rather than to
   `document` — which also retires the stopgap in item 2, since only the menu holding
   focus can receive the keystroke. ArrowLeft in a submenu now returns focus to the
   parent item, and `aria-haspopup` / `aria-expanded` describe the relationship.
4. **[bug] Three different menu widths in one file.** `MENU_WIDTH` is `220` and drives
   the viewport clamp, the rendered menu sets `minWidth: 180`, and `DropdownMenu`'s
   `align: 'center' | 'end'` maths hardcodes `90` / `180`. Centre and end alignment are
   therefore off by up to 40px.
5. **[bug] Submenus close when you move toward them.** `handleItemHover` clears
   `submenuItem` on any item without children, so the usual diagonal pointer path from
   the parent item into the submenu passes over a sibling and dismisses it first.
6. **[bug] Viewport clamping assumes every row is 40px.** Separators are 9px and rows
   vary with content, so `clampMenuPosition`'s height estimate is wrong and menus near
   the bottom of the window still overflow it.

## chart

Reviewed against `LineChart`, which carries the shared scaling helpers; `BarChart` and
`PieChart` reuse `normalizeData` / `getMinMax` and inherit items 1 and 2.

1. **[bug] `getMinMax` inverts the range for all-negative data.** It returns
   `maxY: maxY * 1.1`, and multiplying a negative maximum by 1.1 pushes the top of the
   axis *below* the highest value, so those points scale outside the plot area. It also
   forces `minY: Math.min(0, minY)`, so a series spanning 100–110 is flattened onto the
   top edge.
2. **[bug] Flat or single-point data renders nothing.** With every `y` equal,
   `maxY - minY` is `0` and `scaleY` returns `NaN`; with one point, `scaleX`'s
   `index / (total - 1)` is `0 / 0`. Either way the path becomes `M NaN NaN`.
3. **[bug] `fill` crashes on an empty series.** The area path reads
   `points[points.length - 1].x` without a length check, so one series with no data
   throws.
4. **[bug] The draw animation is hardcoded to 1000 units.** `strokeDasharray` and
   `strokeDashoffset` are both literal `1000` regardless of the real path length, so
   long lines start already partly drawn and short ones finish early and wait.
5. **[bug] Multi-series charts misalign.** X positions use each series' own
   `s.data.length` while the axis labels come from `series[0]`, so series of different
   lengths are each stretched across the full width and no longer share an x axis.
6. **[bug] The injected keyframes are named `dash`** — a global, highly collidable
   name, re-emitted once per chart instance.
7. **[a11y] No accessible representation.** No `role="img"`, no `<title>`, no
   text alternative; the chart is invisible to assistive technology.

## dropzone

Already fixed once this cycle (0.2.0 exposed `rejectedFiles`). What remains:

1. **[bug] `dragenter` throws when `accept` uses extensions.** The drag preview calls
   `isValidFileType({ type: item.type } as File, accept)` with a synthetic object that
   has no `name`. An `accept` entry beginning with `.` takes the
   `file.name.toLowerCase()` branch, so `accept={['.png']}` raises a `TypeError` the
   moment a file is dragged over the zone in Chrome (which, unlike Firefox and Safari,
   does expose `item.type`, so the guard above it passes).
2. **[bug] `multiple: false` leaks the replaced preview.** The state update swaps the
   array wholesale without revoking the outgoing file's object URL; only `removeFile`,
   `clearFiles` and unmount revoke.
3. **[bug] Dropping the same `File` twice corrupts the list.** `createFileWithPreview`
   assigns a fresh `id` onto the *original* File object, so the earlier entry — the
   same object — silently takes the new id. Two rows then share one key and
   `removeFile` deletes both.
4. **[api] The 0.2.0 fix stopped at the hook.** `Dropzone` still never surfaces
   `rejectedFiles`, so a consumer of the component — as opposed to the hook — is back
   to being unable to say why a file was refused.
5. **[api] `onDrop` means two different things.** On `UseDropzoneOptions` it is
   `(accepted, rejected)`; on `DropzoneProps` it is wired to `onDropAccepted` and
   receives accepted files only.

## time

1. **[bug] `minUnit` can produce "0 minutes ago".** When nothing in the filtered unit
   list is large enough, `getTimeUnit` falls back to the smallest available unit and
   still floors — so `formatRelativeTime(d, { minUnit: 'minute' })` on a 30-second-old
   date reports `0`. It should clamp to `1`, or fall through to the "just now" branch.
2. **[bug] `round` can overflow its own unit.** The unit is chosen by flooring, then
   the value is rounded independently, so 3,599 seconds picks `minute` and rounds to
   `60` — "60 minutes ago" where "1 hour ago" was meant.
3. **[bug] `formatDuration` hardcodes English joiners.** The parts come from
   `Intl.NumberFormat` in the caller's locale and are then joined with `' and '` /
   `', and '`, producing "2 heures and 30 minutes" for `locale: 'fr'`.
4. **[bug] Months and years are fixed at 30 and 365 days**, so twelve "months"
   (360 days) never reach one "year" — a date 363 days old reports "12 months ago".
5. **[bug] `useStopwatch` drifts.** It adds a literal `100` per `setInterval` tick
   rather than measuring elapsed wall-clock time, so the readout falls progressively
   behind, badly so in a background tab where timers are throttled.
6. **[perf] `useRelativeTime`'s memo never hits.** Its dependency list contains
   `formatOptions`, the rest-spread object rebuilt on every render.
7. **[bug] SSR renders a different string than hydration.** `now` is seeded with
   `new Date()`, so the server's "2 minutes ago" and the client's differ. Inherent to
   the feature, but it needs a documented escape hatch.

## crop

1. **[bug] The west and north handles slide the box away instead of stopping.**
   Each handle adjusts `x`/`y` and `width`/`height` independently, and only the
   dimensions are clamped afterwards — `x` is never corrected. Drag the `w` handle past
   `minWidth` and the width pins while `x` keeps advancing, so the crop rectangle walks
   across the image under the pointer.
2. **[bug] With `aspectRatio` set, the north and south handles do nothing.** `height`
   is recomputed as `width / aspectRatio` at the end of every update, discarding
   whatever the vertical handles just did — and discarding `minHeight` / `maxHeight`
   along with it.
3. **[bug] The crop area is never bounded by the image.** No clamp against the
   container means the rectangle can be dragged entirely off the picture, and
   `handleMouseDown`/`handleMouseUp` are element-scoped, so releasing the button
   outside the element leaves the drag stuck on.

## command

Partial pass — the palette shell and registration were read, the fuzzy matcher was not.

1. **[bug] The highlight survives an unrelated filter change.** Selection resets in an
   effect keyed on `filteredCommands.length`, so typing a query that swaps one
   five-result set for a different five-result set leaves the highlight on index *N* of
   a list that no longer contains what it pointed at — and Enter then runs the wrong
   command.
2. **[a11y] `role="dialog" aria-modal="true"` with no focus trap and no accessible
   name.** Tab walks straight out into the page behind the palette, and the results are
   plain divs rather than a `listbox`/`option` pair with `aria-activedescendant`, so
   the active result is never announced.

## date

1. **[bug] `parseDate` accepts impossible dates.** Components went straight into the
   `Date` constructor, which rolls over — so `parseDate('13/45/2026')` returned a real
   date in early 2027 instead of `null`. Month and day are now range-checked, and the
   constructed date is verified to round-trip (catching 31 April, 30 February).
2. **[bug] `minDate` / `maxDate` with a time component excluded a whole day.** Cells
   are midnight, so a `minDate` of "today 14:00" compared greater and disabled today.
   Both bounds now compare by calendar day.
3. **[bug] `formatDate` substituted only the first occurrence of each token.**
   `.replace(token, value)` with a string pattern is single-shot, so
   `'MM/DD/YYYY (MM)'` left the second `MM` in place, and each step rescanned text the
   previous ones had already inserted. Now one pass over a combined pattern.
4. **[a11y] The month buttons had no accessible name** — their entire content was the
   glyphs `‹` and `›`.
5. **[a11y] Day cells announced as a bare number.** "30", with no month or year. They
   now carry a full formatted date, plus `aria-current="date"` for today.
6. **[a11y] Keyboard focus was invisible across the grid.** Today's ring was drawn with
   `outline`, which meant every *other* day set `outline: none` and suppressed the
   browser's focus indicator. The ring is now an inset `box-shadow`.

7. **[a11y] No grid semantics and no roving focus** — *fixed in a follow-up (0.3.0)*.
   The month was a flat run of tab stops, so reaching a date meant pressing Tab up to
   31 times. It is now a real `role="grid"` of `row`/`gridcell`, with one day in the
   tab order and arrows / Home / End / PageUp / PageDown moving by day, week and
   month. Days became `aria-disabled` rather than natively `disabled`, since a
   natively disabled button cannot receive focus and would have stopped arrow
   navigation dead at the first out-of-range day.

## card

The best-maintained package in the set — per-input `aria-label`s throughout, logic
split across `useCardInput.ts` / `utils.ts` / `types.ts`. One real defect:

1. **[bug] `onCardTypeChange` and `onValidationChange` fired on every render.** Both
   effects listed the callback itself as a dependency, and inline callbacks change
   identity each render, so neither fired "on change" as documented — and both fired
   once on mount before any input. Same defect as `otp`, fixed the same way.

Noted, not changed: `setCvv` truncates to the length for the card type *at the time of
typing*, so entering a 4-digit Amex CVV and then editing the number to a Visa leaves an
over-long CVV in state. It fails validation, so nothing silently passes.

## timeline

Largely sound — `role="list"` / `listitem`, `aria-current="step"`, real `<button>`s,
key handlers. Two a11y gaps:

1. **[a11y] Interactive entries announced as plain list items.** An entry with an
   `onClick` gets `tabIndex={0}` and a click handler but kept `role="listitem"`, so
   assistive tech gave no indication it could be activated. Interactive entries now
   take `role="button"`; static ones stay list items.
2. **[a11y] The collapsible group header had no `aria-expanded`**, so its state was
   conveyed only by a chevron glyph — which was itself exposed to screen readers and
   is now `aria-hidden`.
